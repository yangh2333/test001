# 外部账号与权限矩阵

版本：v1.0　日期：2026-11-01　依据：E 组 4 题答案 + A2（密级）+ D-2（固定端口代理入站）

---

## 0. 设计原则

1. **独立账号池**：外部账号**不进 LDAP、不进企微**，单独存储、单独认证、单独生命周期管理；
2. **最小可见**：默认不可见，按需逐字段开白名单，宁可多走一次申请；
3. **项目空间即边界**：外部账号只能绑定到具体项目空间，跨项目一律不可见；
4. **全量审计**：外部账号的每一次登录、查看、提交都留痕，留存 180 天；
5. **有明确到期**：所有外部账号必须设到期日，到期自动停用（默认 6 个月，可续期）。

## 3. 密级叠加规则（A2）

外部账号的可见性**与项目密级取交集**——密级优先级高于角色权限：

| 项目密级 | 外部账号可见性 |
| --- | --- |
| 公开 | 按 §2 矩阵执行 |
| 内部 | 按 §2 矩阵执行 |
| 机密 | **所有外部账号一律不可见**，如需供应商协同，单独开"脱敏子空间"（隐藏项目名/型号/客户） |
| 绝密 | 外部账号不可见；不设外部协同通道，改为线下对接 |

密级在**立项时必填**，变更需**双人审批**并留痕（PMO 密级管理员 + 项目负责人）。

## 4. 账号生命周期

```
申请（PM 发起，注明项目/角色/有效期/字段白名单）
   → PMO 审批（权限合理性）
   → 安全审批（仅涉及入站访问时，IT 牵头）
   → 开通（生成邀请链接，一次性，48h 失效）
   → 首次登录强制 MFA 绑定 + 签署保密告知
   → 在有效期内使用（每 30 天提醒续期）
   → 到期自动停用 → 30 天后归档（保留审计不保留数据访问）
```

**强制回收触发条件**：项目结项、合同终止、连续 90 天未登录、项目负责人离职、发生一次违规导出尝试（立即冻结并审计）。

## 5. 技术控制项

| 控制项 | 要求 |
| --- | --- |
| 登录入口 | 仅通过 DMZ 代理机固定端口，与内网入口物理分离（D-2） |
| 会话 | 会话超时 30 分钟；同一账号最多 2 个并发会话 |
| 传输 | TLS 1.2+；代理机终结 SSL，内网段可自签 |
| 导出 | 外部账号**一律禁止任何形式的批量导出**（含导出按钮、打印、另存） |
| 水印 | 页面显示账号名 + 访问时间水印，防截屏外传 |
| 限流 | 单账号 API 限额，异常高频自动冻结 |
| 日志 | 登录、查看、提交、失败尝试全量留痕，留存 180 天 |
| 密码 | 平台独立密码策略；不支持与内部账号互认 |
